### Encryption at Rest

#### Envelope Encryption Pattern

**File:** `backend/shared/Encryption/EnvelopeEncryption.cs`

```csharp
public static (byte[] ciphertext, byte[] iv, byte[] authTag) Encrypt(
    byte[] plaintext,
    byte[] dataEncryptionKey)
{
    using var cipher = new AesGcm(dataEncryptionKey, TagSize: 16);
    // ... AES-256-GCM encryption
}
```

**Flow:**
1. **Data Encryption Key (DEK):** Generated per event or per batch
2. **Key Encryption Key (KEK):** Master key stored in KMS (cloud provider)
3. **Storage:** Encrypted DEK stored alongside encrypted data

**Implementation status:**
- ✅ Encryption utilities implemented
- ⏸️ KMS integration deferred to Phase 1 (cloud provider decision needed)

#### Event Encryption

**File:** `backend/ingestion/Controllers/EventsController.cs`

```csharp
var dataEncryptionKey = EnvelopeEncryption.GenerateDataKey();
var (ciphertext, iv, authTag) = EnvelopeEncryption.Encrypt(payloadBytes, dataEncryptionKey);

var eventEntity = new Event
{
    EncryptedPayload = ciphertext,
    EncryptionIv = iv,
    EncryptionAuthTag = authTag,
    // ...
};
```

**Note:** In production, `dataEncryptionKey` will be encrypted by KMS and stored with the event.

### KMS Key Rotation Policy

**Design (Phase 1 implementation):**

1. **Master Key (KEK):** Automatic annual rotation via cloud KMS
   - AWS KMS: Automatic key rotation enabled
   - Google Cloud KMS: Automatic rotation period set to 365 days
   - Azure Key Vault: Automatic rotation enabled

2. **Data Keys (DEKs):**
   - New DEK generated for each event batch
   - Old DEKs remain valid for decryption (no re-encryption required)
   - DEKs never rotated directly (rotation happens at KEK level)

3. **Rotation Schedule:**
   - KEK: Automatic annual rotation
   - DEK: Generated fresh per use (no rotation needed)

**Documentation:** `docs/security/key-rotation-policy.md` (to be created in Phase 1)

### Retention/Deletion Support

**Schema:** `retention_policies` table

```sql
CREATE TABLE retention_policies (
    id UUID PRIMARY KEY,
    account_id UUID NOT NULL UNIQUE,
    retention_days INTEGER NOT NULL DEFAULT 90,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL,
    updated_at TIMESTAMP WITH TIME ZONE NOT NULL
);
```

**Design for VE-033:**
- Deletion job queries `retention_policies` for retention window
- Deletes events older than retention window by `occurred_at` timestamp
- Cascades to:
  - PostgreSQL `events` table
  - TimescaleDB hypertable partitions (automatic)
  - S3/MinIO archived exports (manual cleanup)
  - Backup snapshots (manual cleanup or TTL)

**TimescaleDB Hypertable:**
```sql
-- Phase 1: Convert events table to hypertable
SELECT create_hypertable('events', 'occurred_at');

-- Automatic partitioning by time
-- Enables efficient deletion of old partitions
```
