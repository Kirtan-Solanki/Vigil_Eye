## Source

- **Security Assessment Risk R-6 (High):** Internal support and legal-hold tooling access to family location and communication metadata is under-specified

---

## Description

Internal support and legal-hold tooling access to family location and communication metadata is currently under-specified. Extend the same "no code path exists to bypass" standard already applied to the on-device indicator to this internal boundary.

---

## Acceptance Criteria

- [x] Internal tooling access is least-privilege, time-boxed, and requires justification per access grant
- [x] All internal/employee access to family data is captured in the audit log (separate from guardian access logs)
- [x] No standing/unscoped admin access to raw family data exists

---

## Implementation

### Database Schema

**AuditLog table** (separate from activity data per Security Assessment §5):

```sql
CREATE TABLE audit_logs (
    id UUID PRIMARY KEY,
    type INTEGER NOT NULL, -- 1 = GuardianAccess, 2 = InternalAccess
    guardian_account_id UUID,
    internal_user_id TEXT,
    child_data_accessed_id UUID,
    action VARCHAR(500) NOT NULL,
    ip_address VARCHAR(45) NOT NULL,
    user_agent VARCHAR(500) NOT NULL,
    accessed_at TIMESTAMP WITH TIME ZONE NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL
);

CREATE INDEX IX_AuditLogs_InternalUserId ON audit_logs(internal_user_id);
CREATE INDEX IX_AuditLogs_Type ON audit_logs(type);
CREATE INDEX IX_AuditLogs_AccessedAt ON audit_logs(accessed_at);
```

### Design Principles

1. **Separate Access Types:** `AccessType.GuardianAccess` vs `AccessType.InternalAccess` in same table but distinguishable via `type` field

2. **No Standing Access:**
   - Internal users do not have persistent access tokens
   - Each access session requires fresh authentication + justification
   - Time-boxed access tokens (4-hour max) for internal tooling

3. **Justification Field:**
   - Every access grant must include a `justification` field
   - Stored in `action` column (e.g., "Support ticket #12345: Parent unable to view call logs")

4. **Least-Privilege Scopes:**
   ```csharp
   public enum InternalAccessScope
   {
       ReadCallLogs = 1,
       ReadLocationHistory = 2,
       ReadAppUsage = 3,
       ExportData = 4,  // For legal-hold requests
       DeleteAccount = 5  // Requires elevated approval
   }
   ```

## Admin API Design (Phase 1 Implementation)

### Endpoints

#### `POST /api/v1/admin/access-requests`
Request time-boxed access to family data.

**Request:**
```json
{
  "internal_user_id": "employee@company.com",
  "child_id": "uuid",
  "scope": ["ReadCallLogs", "ReadLocationHistory"],
  "justification": "Support ticket #12345: Parent unable to view call logs",
  "duration_hours": 4
}
```

**Response (200 OK):**
```json
{
  "access_token": "temp-admin-token",
  "expires_at": "2026-09-13T18:00:00Z",
  "scope": ["ReadCallLogs", "ReadLocationHistory"]
}
```

#### `GET /api/v1/admin/audit-logs`
Query audit logs for compliance review.

**Requires:** Elevated admin role (e.g., Security Officer)

## Access Control Enforcement

### Middleware (Phase 1 Implementation)

```csharp
public class InternalAccessMiddleware
{
    public async Task InvokeAsync(HttpContext context)
    {
        if (IsInternalAccessRequest(context))
        {
            var token = ExtractAccessToken(context);
            
            // Verify token is not expired
            if (token.ExpiresAt < DateTime.UtcNow)
            {
                return Unauthorized("Access token expired");
            }
            
            // Verify scope covers requested action
            if (!token.Scope.Contains(context.Request.Path))
            {
                return Forbidden("Insufficient scope");
            }
            
            // Log access attempt
            await LogAccessAsync(token, context);
        }
        
        await _next(context);
    }
}
```

## Test Plan

### Unit Tests

1. **Test access request requires justification**
   - POST access request without justification → 400 Bad Request

2. **Test time-boxed token expiry**
   - Request 4-hour access
   - Wait 5 hours
   - Attempt data access → 401 Unauthorized

3. **Test scope enforcement**
   - Request `ReadCallLogs` scope only
   - Attempt to access location data → 403 Forbidden

4. **Test audit log separation**
   - Guardian accesses data → logged as `GuardianAccess`
   - Internal user accesses data → logged as `InternalAccess`
   - Verify separate query paths

### Integration Tests (Phase 1)

1. Support staff requests access → granted with limited scope
2. Support staff accesses data → audit log entry created
3. Token expires → access denied
4. Security Officer queries audit logs → all entries visible
